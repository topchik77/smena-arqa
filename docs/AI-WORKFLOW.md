# Как использовался ИИ при разработке

Этот файл описывает реально выполненную работу, а не приписывает кандидату неподтверждённый опыт.

## Разделение работы

Работа велась с Codex. Один агент исследовал первичные источники Uber, Яндекс Про и руководства по доступности и подготовил дизайн. Второй реализовал и проверил Python API, третий — Flutter-клиент. Основной агент согласовал контракт, подготовил окружение и запуск, проверил интеграцию через браузер и оформил документацию. После реализации агент backend отдельно просмотрел клиентский код.

ИИ помог с исследованиями, реализацией, тестами и ревью. Результаты проверялись командами сборки, автоматическими тестами, реальными HTTP-запросами и действиями в интерфейсе. Наличие написанного теста само по себе не считалось доказательством: проверялся его запуск.

## Где первоначальный результат потребовал исправления

| Проблема | Как обнаружена | Принятое исправление |
|---|---|---|
| Первоначальный разбор дня повторял сводку | Пользователь указал на отсутствие пользы | Сравнение с предыдущим заполненным днём: доход, число поездок и средний доход; отдельные проверки пограничных случаев |
| В первоначальном API проверка типа timestamp позволяла строку с UNIX-числом вместо ISO 8601 | Независимый просмотр Pydantic-валидации | Явная проверка формата и регрессионный тест |
| Предварительная версия клиента допускала другую максимальную сумму, чем сервер | Сверка контракта на ревью | Одинаковый предел в форме и API |
| После потерянного ответа новый отказ мог стереть сохранённый ID | Ревью последовательности timeout → повтор → 429 | Сохранение неопределённой операции до подтверждения |
| Упрощённое смещение UTC+5 не покрывало исторические даты Алматы | Сверка серверной IANA-зоны с клиентским кодом | IANA-преобразования времени на клиенте |
| Клиент мог принять пустой JSON с HTTP 200 за подтверждение сохранения | Ревью сетевого слоя | Проверка возвращённой поездки перед подтверждением |
| Переключение дня во время начальной загрузки влияло на последующее обновление | Проверка порядка асинхронных ответов | Исправление состояния инициализации и тест гонки |

Перечисленные исправления внесены. Конкретные проверки находятся в `backend/tests/` и `client/test/`; фактический прогон описан в [VERIFICATION.md](VERIFICATION.md).

## Что кандидат должен проверить лично перед отправкой

Открыть приложение на своём телефоне (веб-версию на iPhone или APK на Android), повторить [DEMO.md](DEMO.md), прочитать основные решения и объяснить их своими словами. В анкете нельзя утверждать, что эти исправления были найдены вручную самим кандидатом, если фактически их выявили ИИ-агенты. Можно честно описать организацию процесса, проверки и собственные решения после изучения результата.
